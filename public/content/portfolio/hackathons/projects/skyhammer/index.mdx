# Introduction

**Project SkyHammer** is an autonomous cybersecurity AI system for vulnerability detection, exploitation, and remediation, with an RLAIF training pipeline for teaching smaller models to write secure code.

The project originated at the **xAI Grokathon** in **January 2026** in Central London, where it was built using xAI's Grok model. It was then further developed at the **Gemini 3 Hackathon 2026**, where it was rebuilt and extended using Google's Gemini model — adding distributed training infrastructure, DPO pipelines, and multi-GPU support.

# Architecture and Approach

SkyHammer operates in three modes:

1. **ATTACK Mode** — Scans code for vulnerabilities, attempts exploits, and generates detailed reports with severity ratings, proof-of-concept curl commands, and before/after code comparisons.
2. **DEFENSE Mode** — Generates secure patches with split-pane diff visualization, backup/rollback support, and workspace sandboxing.
3. **LEARN Mode** — RLAIF training pipeline using a frontier model as a judge to train smaller models via SFT, DPO, and GRPO.

The core of the project is an **interactive CLI** with an Evangelion/Cyberpunk aesthetic, featuring NERV-style system banners, real-time progress spinners, and split-pane diff visualization for vulnerability reports.

**Vulnerability types covered:** SQL Injection, XSS, Command Injection, Path Traversal, Hardcoded Secrets.

# Grokathon Version (Grok / xAI)

The original Grokathon build used Grok as the teacher model in an RLAIF pipeline:

1. **Student Model** (Qwen 14B, local) generates patches for vulnerable code
2. **Teacher Model** (Grok API) scores the patches using a hybrid reward function (0.0 to 1.0)
3. **GRPO Weight Update** — Generate 4 patches per vulnerability, Grok scores them, update LoRA adapters
4. **Benchmark** — Compare SkyHammer-RLAIF against base Qwen-14B and frontier models across 50 synthetic SQL injection vulnerabilities

The target was to demonstrate that a small local model trained via RLAIF using Grok as a teacher can outperform its base model by 45%+ and approach the performance of frontier models at a fraction of the cost.

**Tech stack:** Python, Grok API (xAI), Rich CLI, LoRA/PEFT, GRPO training on H200 GPU.

# Gemini Hackathon Version (Gemini / Google)

The Gemini Hackathon build extended the system with larger models and distributed training:

**Training Infrastructure:**
- Model: Devstral 2 123B (mistralai) with FP8/BF16 mixed precision on H200 GPUs
- Training: DeepSpeed ZeRO-3 + LoRA (later migrated to FSDP due to DeepSpeed+LoRA incompatibility)
- Dataset: 116 examples of vulnerable-to-secure code transformations, uploaded to HuggingFace
- Fallback: Mistral-Small 24B verified working on A100 GPUs

**Key Technical Challenges Solved:**
- Discovered and documented that DeepSpeed + LoRA is fundamentally broken in v0.12+ with PyTorch 2.4
- Solved FP8 model loading issues (A100 cannot natively handle FP8 — requires H100/H200 Hopper architecture)
- Fixed FSDP weight synchronization issues with large model sharding
- Resolved TRL API breaking changes (v0.13+)
