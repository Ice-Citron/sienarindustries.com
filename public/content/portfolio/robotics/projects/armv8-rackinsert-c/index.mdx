# ARMv8-RackInsert-C

Every robotics competition I’ve done handed me their custom-built evaluator. From March 2026 to June 2026, I took part in the Intrinsic’s AI for Industry Challenge (read more here). In this competition, the scene, the scoring and held-out trials all arrived ready-made, and our job as participants is to only handle the robot policy. 

This phenomenon left behind a vacuum in my understanding, that is, I never had the opportunity to build and grok the backend which evaluates my policy and produces a score. This is especially important for someone like me who’s very interested in sim-to-real, because designing the evaluation infrastructure is practically what sim-to-real mostly is. Hence, when Imperial allowed me to build whatever I wanted for my first-year C project’s extension, I decided to build my own naive version of the AIC evaluation engine—in a level lower than the original built by Intrinsic which used C++/ROS 2 Kilted—using C and the MuJoCo’s C API.

# The Project

The extension, my favourite part, was the fourth part of the final group project of Imperial’s first-year C programming course. The group project was done by a team of four (Ryan Wong, Rayan Abdallah, Rahul Babu and me) over three weeks in June 2026. The project has three fixed components and a fourth open-ended section allowing us to build whatever we want. 

For the required parts, we built:

- An ARMv8 assembler which converts assembly source code to machine code 
- An ARMv8 emulator which executes a subset of the AArch64 instruction set and prints the final register and memory state
- A Raspberry PI program which uses its memory-mapped GPIO registers to blink an LED connected to the RPi.

My teammates wrote the ARMv8 emulator and the RPi GPIO program, whilst I wrote a large part of the assembler, and all of the extension. 

For the extension, I built RackInsert-C. RackInsert-C is my own version of the evaluation engine (the AIC eval_engine) from Intrinsic’s AI for Industry Challenge, written with MuJoCo’s C API. My evaluation engine loads the scene sourced from Intrinsic’s competition, then runs a scripted dummy policy on the UR5e arm and measures where the TCP (plug tip) ends up relative to the socket, and scores the trial. For this project, the robot controller is deliberately a dummy policy that waves, not a real cable-insertion policy: the goal was to to show that the evaluation engine loads the scene, runs the trial and produces a score end-to-end, and a proper policy on top of it is a different research project that I’m currently tackling.
